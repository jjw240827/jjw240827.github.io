10828번은 스택 라이브러리에서 제공하는 push, pop과 같은 기능들을 내가 직접 구현하는 문제인데 학교 알고리즘 책에서 예제로 나온 기억이 있어서 전체적인 틀을 짜기 편했다.


## 생성자 컴파일 에러
public class Node {
    Object data;
    Node next;
 public Node() {
        Node node;
        Node output;
    }
}
생성자를 통해서 빈 객체 node, output을 만들어서 스택을 구현하려 했는데 node나 output이 들어가는 모든 곳에 cannot find symbol오류가 발생했음. 하지만 생성자를 없애고 지역 변수로써 node와 output을 만들어서 사용하니 오류가 사라짐. 

찾아보니 그 원인은 괄호안에서 만들어진 즉, 생성자나 매서드 안에서 만들어진 변수는 지역 변수이니 사용이 불가능한 단순한 이유였다. 생성자를 통해서 변수를 생성하면 생성자 역시 매서드이므로 지역변수가 되는 것이 당연하지만 Node node 즉, 객체를 만들었으므로 지역변수와 다르게 사용될 것이라고 생각했었떤 것 같다. 하지만 new Node()를 붙이지 않았으므로 아직 heap 생성도 되지 않은 변수이다.
그렇다면 만약 생성자를 통해 객체를 생성했었으면 사용이 가능했을까? 
불가능하다 객체는 heap 메모리에 독립적으로 존재하므로 주소만 안다면 어디서든 접근이 가능하지만 중요한 주소를 담고있는 변수가 지역적인 지역 변수이기 때문에 다른 곳에서 사용이 불가능하다. 이걸 극복하기 위해서는 변수를 멤버 변수로 만들고 생성자를 통해서 해당 멤버 변수에 객체를 대입하는 방식을 사용하는 것이 좋겠다.

## Object

Node의 data를 Object형으로 사용하였는데 가장 위에있는 값을 뺴는 pop이나 top 메서드에서 반환된 Object형을 int형으로 받으려고 하여서 오류가 발생함. Object형이 모든 자료형의 부모 클래스이므로 당연히 int로 바뀔 수 있다고 생각을함.
그렇다면 int형을 Object 변수에 담을 수 있을까?

int는 기본 자료형이여서 객체가 아니지만, 자바가 자동으로 Integer라는 래퍼 클래스로 감싸서 Object의 자식으로 만들기에 반환된 int형을 Object 변수에 담는 것이 가능하다.
