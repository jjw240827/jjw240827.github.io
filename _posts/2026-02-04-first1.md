자바 웹 개발 워크북 책을 보면서 공부하던 중 cookie의 내용을 배우면서 session과 cookie, token의 차이와 정의가 모호하고, 궁금해져서 정리하게 되었다.

## http
http는 HyperText Transfer protocol의 약자로써 서버와 클라이언트가 데이터를 주고 받기 위한 프로토콜이다. 
http는 프로토콜 즉, 데이터 송/수신의 간의 약속이고 http로 데이터를 송/수신 하는 방식이 바로 tcp이다. 

http는 중요한 특성이 존재하는데 첫 번째가 비연결지향성이고, 두 번째가 무상태성이다. 즉, 서버와 클라이언트 간의 요청, 응답이 끝나면 연결이 끝나며, 연결이 끝나면 클라이언트의 상태 정보를 가억하지 않는다.

연결을 지속하지 않고 클라이언트의 상태 정보를 기억하지 않으면 자원을 적게 사용할 수 있고, 

하지만 우리가 사용하는 대부분의 웹 사이트에 존재하는 자동 로그인 기능과 같은 해당 클라이언트에 대한 정보를 가지고 있어야 제공할 수 있는 서비스는 상태 정보를 저장하고 사용해야 한다. 이를 위해서 cookie, session, token과 같은 도구를 사용한다.
## cookie
쿠키는 key - vlaue의 형태로 해당 사이트의 브라우저에 보관한다. 브라우저 내부에 저장된 쿠키는 발급받은 도메인 사이트에 요청을 할 때 자동으로 해당 http요청에 추가되어서 보내진다. 즉, 브라우저가 내부 저장소에 도메인별로 쿠키를 관리한다. 쿠키는 개발자가 유효 기간을 지정할 수 있고 만약 유효 기간이 끝난 쿠키가 있다면 요청시에 보내지 않고 응답할 시에 새로운 쿠키를 발급할 수 있다.

그러면 쿠키를 이용해서 정보를 수집해서 광고에 사용한다는 이야기를 들은 적이 있는데 도메인 별로 브라우저가 쿠키를 관리한다면 어떻게 광고를 위한 정보를 습득하는 것이 가능할까?
특별한 쿠키를 사용하는 것이 아닌 마찬가지로 특정 브라우저에 요청할 때만 해당 쿠키가 사용되는데 이 때 특정한 사이트에 들어가서 뜬 광고 창 중에서 내가 가지고 있는 쿠키가 있으면 자동으로 해당 광고 도메인에 http요청을 하게 되어서 사용자가 어떤 사이트를 주로 접속하는지 알 수 있게 되는 원리이다.

하지만 session이 추가적으로 사용되는 이유는 쿠키는 사용자가 직접 그 내용이나 값을 볼 수 있는 만큼 탈취 당할 가능성이 높아서 로그인 정보와 같은 중요한 정보에는 사용하지 못한다. 이를 보완하기 위해 세션을 사용한다.
## session
세션은 쿠키와 달리 서버 내부의 저장소에 사용자에 대한 정보를 저장하는 방식이다. 그렇기 때문에 사용자에 대한 정보에 대한 보안이 강화되어서 자동 로그인과 같은 서비스를 세션을 통해 구현을 할 수 있다. 요청을 받으면 해당 요청에서 저장해야하는 정보들을 서버 내부 저장소에 저장을 하고, 각 사용자의 정보를 구별할 수 있는 세션ID를 생성하여 response시 사용자에게 보낸다. 사용자는 해당 정보를 쿠키로 저장하여 매 request 시 세션 ID를 보내어서 서버 내부 저장소에 있는 세션 ID와 대조하여 사용자 권한을 확인, 인증한다.

하지만 마찬가지로 cookie에 세션ID가 저장되어져 있기에 탈취 당할 수 있고, 서버 확장성이 나빠진다. 서버 확장성이 나빠진다는 뜻은 사용자가 하나의 서버에 종속될 수 있다는 뜻이다. 특정한 작업을 하지 않으면 한 서버의 내부 저장소에 사용자의 정보가 저장이 되고 만약 해당 서버가 고장 등의 이유로 교체되거나 재부팅이 될 경우 그 정보들을 사용자의 세션 ID와 대조할 수 없기에 한 서버에 종속될 수 있다고 말한다.
